# ExportAI 产品需求文档（PRD）

## 1. 项目信息

| 字段 | 值 |
|------|-----|
| Project Name | `exportai` |
| Language | 中文 |
| Programming Language | 后端: Node.js (Express) / 前端官网: Next.js / 扩展: Manifest V3 |
| 版本 | v2.0.0（SaaS 升级版） |

### 原始需求复述

将 ExportAI 从纯本地浏览器扩展升级为 SaaS 产品：
1. 添加账号密码登录注册系统
2. 搭建官网（参考 ExportGPT.pro 暗色 SaaS 风格）
3. 全栈 Docker 化部署

---

## 2. 产品定义

### Product Goals

1. **用户身份体系**：建立完整的注册/登录/认证系统，为用户管理和未来商业化奠定基础
2. **品牌与分发**：通过官网着陆页建立产品品牌形象，提供安装入口和功能展示，提升用户获取效率
3. **运维标准化**：通过 Docker Compose 实现一键部署，降低运维复杂度，保障服务稳定性

### User Stories

| # | 用户故事 |
|---|---------|
| US1 | 作为用户，我可以在官网注册账号，以便使用 ExportAI 的云端服务 |
| US2 | 作为用户，我可以在扩展 Popup 中登录/登出账号，以便同步我的使用数据 |
| US3 | 作为用户，我可以通过邮件链接找回密码，以便在忘记密码时恢复账号 |
| US4 | 作为用户，我可以在官网了解产品功能并一键安装扩展，以便快速上手使用 |
| US5 | 作为管理员，我可以查看用户列表和使用统计，以便了解产品运营状况 |

## 3. 技术规范

### Requirements Pool

#### P0 — Must Have

| ID | 需求 | 说明 |
|----|------|------|
| P0-01 | 用户注册 | 邮箱 + 密码注册，密码 bcrypt 加密存储 |
| P0-02 | 用户登录 | 邮箱 + 密码登录，返回 JWT (access + refresh token) |
| P0-03 | JWT Token 认证 | access token 短期有效（15min），refresh token 长期有效（7d），自动刷新 |
| P0-04 | 密码找回 | 发送邮件重置链接，链接有效期 30 分钟 |
| P0-05 | 后端 REST API | Express + TypeScript，提供 /auth/* 系列接口 |
| P0-06 | 数据库 | PostgreSQL，用户表 + 使用记录表 |
| P0-07 | 官网着陆页 | 暗色主题 SaaS 风格，Hero → 功能 → 评价 → FAQ → CTA |
| P0-08 | Chrome 扩展登录集成 | Popup 中集成登录/登出/用户状态展示 |
| P0-09 | Docker Compose 部署 | 后端 + PostgreSQL + 官网前端，一键 `docker-compose up` |

#### P1 — Should Have

| ID | 需求 | 说明 |
|----|------|------|
| P1-01 | 用户使用量统计 | 记录导出次数、格式分布等，扩展端上报 |
| P1-02 | 管理后台 | 用户列表、统计看板，基础 CRUD |
| P1-03 | 记住登录状态 | refresh token 持久化，重启浏览器免登录 |
| P1-04 | 修改密码 | 已登录用户可修改密码 |

#### P2 — Nice to Have

| ID | 需求 | 说明 |
|----|------|------|
| P2-01 | OAuth 第三方登录 | Google、GitHub OAuth |
| P2-02 | 付费订阅 | Stripe 集成，免费/Pro 套餐 |
| P2-03 | 导出历史云端同步 | 多设备同步导出记录 |
| P2-04 | 多语言支持 | 官网和扩展 i18n |

## 4. UI 设计说明

### 4.1 官网着陆页

**整体风格**：现代 SaaS 工具产品，暗色主题 + 渐变紫色系，参考 ExportGPT.pro

**配色方案**：
- 背景：`#0a0a0f`（深黑紫）
- 主色渐变：`#6366f1` → `#8b5cf6`（靛蓝紫 → 紫罗兰）
- 文字：`#f5f5f5`（主文字）/ `#a1a1aa`（次要文字）
- 强调：`#22d3ee`（青色，CTA 按钮）

**页面结构**：

| 区块 | 内容 |
|------|------|
| **Hero** | 标题 "一键导出 AI 对话，支持 9 大平台 + 9 种格式"；副标题 + "免费安装" CTA 按钮；产品截图/GIF |
| **痛点共鸣** | "还在手动复制粘贴 AI 对话？" → 3 个痛点卡片 |
| **核心功能** | 3-4 个功能卡片：多平台支持、多格式导出、一键操作、自动导出 |
| **用户评价** | 3 条用户引言卡片，含头像/昵称/身份 |
| **FAQ** | 6-8 个常见问题折叠面板 |
| **底部 CTA** | "立即免费安装" + Chrome Web Store 链接 |

**登录/注册**：
- 独立页面（`/login`, `/register`），与着陆页同风格
- 表单居中，暗色卡片背景
- 注册页：邮箱 + 密码 + 确认密码
- 登录页：邮箱 + 密码 + "忘记密码？" 链接
- 忘记密码页：输入邮箱 → 发送重置链接 → 跳转重置密码页

### 4.2 扩展 Popup 登录集成

**未登录状态**：
- Popup 顶部显示 "登录以同步数据" 提示
- 点击弹出内嵌登录面板（邮箱 + 密码 + 登录按钮 + 注册链接）
- 登录面板与 Popup 一体，不跳转新页面

**已登录状态**：
- Popup 顶部显示用户头像（默认首字母） + 邮箱
- 下拉菜单：使用统计、修改密码、登出
- 登出后清除本地 token，回退到未登录状态

```
┌─────────────────────────────────────────────────┐
│                 Docker Compose                   │
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌───────────────┐  │
│  │ 官网前端  │  │ 后端 API  │  │  PostgreSQL   │  │
│  │ Next.js  │  │ Express  │  │   数据库       │  │
│  │ :3000    │  │ :4000    │  │   :5432       │  │
│  └──────────┘  └──────────┘  └───────────────┘  │
│                                                  │
│  ┌──────────────────────────────────────────┐    │
│  │         Chrome Extension (Manifest V3)    │    │
│  │  Popup 登录 ←→ 后端 API ←→ 数据库       │    │
│  └──────────────────────────────────────────┘    │
└─────────────────────────────────────────────────┘
```

### API 接口规划（P0）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/register` | 用户注册 |
| POST | `/api/auth/login` | 用户登录 |
| POST | `/api/auth/logout` | 用户登出 |
| POST | `/api/auth/refresh` | 刷新 token |
| POST | `/api/auth/forgot-password` | 发送重置邮件 |
| POST | `/api/auth/reset-password` | 重置密码 |
| GET  | `/api/auth/me` | 获取当前用户信息 |

### 数据库表设计（P0）

**users 表**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| email | VARCHAR(255) | 唯一，邮箱 |
| password_hash | VARCHAR(255) | bcrypt 加密 |
| created_at | TIMESTAMP | 注册时间 |
| updated_at | TIMESTAMP | 更新时间 |

**refresh_tokens 表**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| user_id | UUID | 外键 → users |
| token | VARCHAR(500) | refresh token |
| expires_at | TIMESTAMP | 过期时间 |
| created_at | TIMESTAMP | 创建时间 |

### 技术选型

| 组件 | 选型 | 备注 |
|------|------|------|
| 后端框架 | Express + TypeScript | 轻量，扩展生态好 |
| 数据库 | PostgreSQL | 推荐，JSON 支持好 |
| ORM | Prisma | 类型安全，迁移方便 |
| 认证 | JWT (access + refresh) | 业界标准 |
| 密码加密 | bcrypt | 安全性高 |
| 官网前端 | Next.js | SEO 友好，SSR |
| 扩展技术 | Manifest V3 | 已有基础 |
| 容器化 | Docker Compose | 一键部署 |
| 邮件服务 | 待确认 | Resend / SendGrid |

## 6. 待确认问题

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | 数据库选型：PostgreSQL vs MySQL？ | 开发效率、功能支持 | 推荐 PostgreSQL（JSON 字段、全文搜索、扩展性好） |
| 2 | 邮件服务选型 | 密码找回功能 | 推荐 Resend（开发者友好，免费额度够用） |
| 3 | 域名 | 官网部署 | 需确认是否已有域名，或注册新域名 |
| 4 | 服务器/部署环境 | Docker 部署配置 | 需确认部署平台（云服务器/VPS） |
| 5 | CORS 策略 | 扩展调用 API | 需配置扩展 ID 为允许来源 |
| 6 | 密码策略 | 安全性 | 最小长度？是否要求特殊字符？建议 ≥8 位 |
